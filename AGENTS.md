# Инструкции для агентов

- Имя проекта — `teza`, backend — `teza-backend`. Пользовательская документация
  пишется кратко по-русски; команды нужны для PowerShell, macOS и Linux.
  Операционные заметки агентам хранить здесь, а не в README.
- Общие требования — в `../teza/docs/SPECIFICATION.md`, `ARCHITECTURE.md`
  и `RESEARCH-DATA.md`. Последующие уточнения пользователя имеют приоритет.
- Java 21, Spring Boot, PostgreSQL/Flyway, Maven wrapper. Модули — пакеты
  предметных областей внутри одного приложения, а не отдельные микросервисы.
- Следовать KISS, DRY, SOLID и YAGNI. Не создавать пустые модули, универсальные
  framework и интерфейсы для каждого класса. Отдельный интерфейс нужен
  на реальной границе замены, например для AI-движка.
- HTTP DTO отделять от JPA-сущностей. Доступ проверять на сервере;
  сессии редактора используют CSRF-защиту. Не отключать её ради тестов.
- Долговечная схема меняется миграциями Flyway. Не заменять PostgreSQL на H2
  в интеграционных тестах и не включать автоматическое создание схемы Hibernate.
- Запускать `./mvnw verify` (Windows: `.\mvnw.cmd verify`); Docker обязателен
  для интеграционных тестов. Сообщать отдельно о проверенных и непроверенных ОС.
- Не хранить секреты в Git или логах. Не собирать профили участников дискуссий,
  не сохранять их персональные данные и необработанные внешние комментарии.
- Подтверждённый граф и ручные правки не зависят от провайдера AI.
  Структурированные предложения проходят серверную валидацию и проверку человеком.
- Использовать существующий checkout. Не создавать worktree без явной просьбы.
  Не менять соседние репозитории без необходимости текущей задачи.
- Перед завершением проверить diff, выполненные тесты и соответствие README
  реальным настройкам запуска. Не коммитить и не отправлять изменения без задачи.

## Облачная среда

- Полный JDK 21 подготовлен в `/workspace/.cache/teza-tools/jdk21`;
  системная Java может не содержать полного комплекта для `--release 21`.
  Перед использованием проверить наличие каталога, не переносить этот путь в POM.
- Maven-настройки прокси находятся в `/tmp/teza-maven-settings.xml`, локальный
  кэш зависимостей — `/workspace/.cache/m2`. Если временный файл отсутствует,
  восстановить его из текущих настроек среды, сохраняя TLS-проверку.
- Для Docker-сборки за прокси предусмотрены необязательные BuildKit secrets
  `maven_settings` и `java_truststore`. Внутри контейнера адрес прокси должен
  быть разрешим; доверенное хранилище содержит штатный CA среды. Облачные
  override-файлы и значения не добавлять в пользовательскую конфигурацию.
- Проверено на Linux: `verify` (25 тестов), Compose build/up/down/up,
  HTTP-вход/CSRF/CRUD и сохранность данных, запуск через Maven с `.env`.
  Команды PowerShell и macOS документированы, нативно здесь не выполнялись.
